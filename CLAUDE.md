# AwaazForm

Assistive form filling (Katathon 6.0, PS 402). Users complete Google Forms, Microsoft Forms, PDFs and Word files by voice or text, in English, Hindi and Marathi (branch `alternate`: these three only, done well, rather than 13 done thinly). Each answer is read back and filled only after the user confirms. AwaazForm never submits. The full spec is the PRD (v2.0) that the user provided, and it is the source of truth for scope.

## Non-negotiables (PRD §9, enforced in `packages/core`)

- Writes reach a form only through `SessionController.confirm()`, which only the UI calls. There is no confirm tool for the model.
- The model acts only through the tools in `packages/core/src/tools.ts`, and the runner validates every argument with Zod.
- Never submit forms. Never fill passwords, OTPs, CAPTCHAs, payment or auth fields. Never save the sensitive categories in `safety.ts`.
- `GROQ_API_KEY` is used only in the API (`backend/app/groq.py`). Personal data stays in the browser.
- Report only accuracy, latency or success numbers that were actually measured.

## Design theme: mirrors specifyapp.com (keep it)

All UI follows the Specify-derived theme. Never hard-code colours, radii, shadows or easings. Use the CSS variables in `apps/web/app/globals.css`.

- **Palette:** white / `--gray-100` surfaces, `--ink-900` text, `--violet-500` (#624DE3) as the single accent. Use `--text-muted` (ink-600) for small muted text so it keeps AA contrast.
- **Type:** Inter for headings (600, tight negative tracking) and body, Noto Sans Devanagari for Hindi, Fira Code for transcripts and code. Section heads are centred with a two-line `<br />` break and a muted subtitle beneath.
- **Section rhythm:** centred head, then a button pair (primary violet + white ghost), then content. Use `.card` (`--r-24`, white→gray-100 gradient, 1px border).
- **Signature moves:** hero product shot on a violet glow fading into an `--ink-950` band; edge-masked `.marquee`; a violet→dark rounded panel; a dark pill badge.
- **Motion:** `<Reveal>` in `components/Motion.tsx` replicates Framer's appear effect (fade + 20–30px rise, 0.4s, `[0.44,0,0.56,1]`). Every animation must respect `useSettings().reduceMotion` (FR-28).
- **Accessibility (WCAG 2.2 AA):** 44px minimum targets (`.btn` has them), visible focus, `aria-live` for announcements, no meaning carried by colour alone. Themes: `data-contrast="high"` and `data-text="large"` on `<html>`.
- **Motif:** `<Wave />` waveform.

## Structure

- `packages/core`: shared types, normalizers, validators, safety rules, session reducer, controller (confirm gate), tool runner, report, profile crypto, Google and Microsoft Forms parsing and pre-fill, option matching (`normalize`), prompts and the form outline. Tests and the test form fixture are in `test/`.
- `apps/web`: Next.js 16 app. Routes: `/`, `/form` (Google or Microsoft Form by link), `/documents` (PDF and Word in one drop zone: `components/documents/{PdfFlow,DocxFlow}`; `/pdf` and `/docx` redirect here), `/extension` (download and install the extension), `/replica` (iframe animation surface), `/report`, `/profiles`, `/settings`, `/privacy`. Built as a static export (`output: 'export'` → `apps/web/out`) that `backend/app/web.py` serves with the API on one origin, adding the security headers (CSP mirrors `next.config.ts`), clean URLs (`/form` → `form.html`), the `/pdf`·`/docx` redirects and the share-target fallback. No server-only Next features (route handlers, `next/headers`, dynamic routes) on this branch. In `next dev`, `/api/*` is proxied (`BACKEND_URL`) to the API. e2e tests mock `/api/gform` with a raw Google page (`e2e/mock-gform.mjs`), so question ids are `g1…`.
  - **i18n:** every interface string is in `lib/i18n/en.ts` (the source; `{placeholders}`, `<b>`/`<code>`/`<br/>` via `<Rich>`). `node scripts/translate.mjs [langs] [--force]` generates `lib/i18n/locales/<code>.json` with Groq and checks keys, placeholders and tags; it only redoes keys whose English changed (`_source`). Missing keys fall back to English. Messages produced in English by code (validation, parsers, servers) are translated at display time with `localizeMessage` (`msgs` keyed by the English text, `msg_patterns` for ones with values). Never hard-code UI text; add it to `en.ts`. Urdu is RTL (`dir` on `<html>`); use logical CSS (`ms-`, `ps-`, `start`).
  - **Security:** profiles use envelope encryption (random AES-256-GCM data key, wrapped by the PBKDF2 passphrase key and optionally by a passkey via WebAuthn PRF, `lib/passkey.ts`); v1 profiles upgrade on unlock; unlocked keys live in memory and lock after 10 min idle (`lib/vault.ts`). Sessions and uploaded files are encrypted at rest with a non-extractable device key and expire after 24 h (`lib/secure-store.ts`). The privacy shield (`packages/core/src/pii.ts`) swaps emails, phones, Aadhaar, PAN and long numbers for placeholders before text reaches the AI and restores them locally.
  - `components/SessionWorkspace.tsx` is the one session UI (question card, option picker, read-back/confirm, Live Mode with conversation log, stepper, Form/Activity tabs). Sources plug in a `SurfaceHandle` (`lib/surface.ts`): `ReplicaSurface` for forms, `PdfSurface` for PDFs, `DocxSurface` for Word, and the `/extension` page's surface, which writes through the extension.
  - `/form` scans a public Google Form (`/api/gform`) or Microsoft Form (`/api/msform`), hosts allow-listed and each redirect hop checked. Google answers go back as a pre-filled link (`googlePrefillUrl`); Microsoft only when the owner set `AllowPrefill` (`microsoftPrefillUrl`), otherwise a copy-answers dialog. Only verified answers are handed back; the user submits.
  - Live Mode: the model gets the current question plus a form outline (labels, types, options, done flags; never answer values), so one utterance can `propose_fill` several questions or correct an earlier one; `go_to_question` only navigates. Short spoken answers to option questions skip the model when `matchOption`/`matchOptions` (ordinals, Hindi/Marathi words, synonyms, fuzzy) match unambiguously.
  - `lib/pdf.ts` handles PDF analysis, box placement and filling; `lib/docx.ts` finds and fills `.docx` blanks, ☐ boxes, empty table cells and content controls (fflate + DOMParser, in the browser); `lib/live.ts` is Live Mode's voice detection; `lib/bolu.ts` is Bolu (animated SVG, framework-free, shared with the extension; `components/Bolu.tsx` wraps it); `lib/api.ts` sets the API base (empty on the site, the server URL in the extension).
- `apps/extension`: MV3, built with esbuild (`node apps/extension/build.mjs`, run by the web `prebuild`; outputs `dist/` and `apps/web/public/downloads/awaazform-extension.zip`). `content.js` mounts Bolu's widget (`widget.html`, an extension iframe in a closed shadow root) on form pages and fills/reads fields; `src/widget.ts` runs the session loop with the web libs (alias `@` → `apps/web`); `background.js` relays widget ↔ page with extension messaging only. It never clicks Submit and skips password fields.
- `backend` (branch `alternate`): FastAPI, `uv run uvicorn app.main:app`. Routes `/api/{chat,stt,tts,extract,gform,msform,translate,health}` (translate: the form's own questions and options into the interface language, `lib/question-i18n.ts`, cached per form). `app/guard.py` admits the web app's origins (`ALLOWED_ORIGINS`, or `Sec-Fetch-Site: same-origin`) and the extension (CORS); everything else gets 403. `gform`/`msform` only fetch (allow-listed hosts, every redirect hop checked, 4 MB cap); the browser parses with core (`lib/form-scan.ts`). Prompts and tool declarations come from core via `node scripts/export-contract.mjs` → `backend/app/contract.json`; rerun it after changing `prompts.ts` or `tools.ts`. Speech: the device's own voice first (`lib/voice.ts`), then Kokoro ONNX on the server (`app/tts/engines.py`; en, hi, and mr through the Hindi voice with espeak's Marathi rules; no PyTorch), downloaded to `backend/models/` on first use (`uv run python -m app.download` fetches it ahead); `TTS_PRELOAD` warms it at startup. Hearing: the browser's own recognition first (`lib/web-speech.ts`: Chrome/Edge, live words, 3 alternatives for “or did you say”), Groq Whisper as the fallback (Brave, Firefox, offline). Names, emails and numbers are heard as Indian English (`recognitionLocale`/`sttLanguage`) so names come back in English letters. Rules before AI: `quickValue`, `extractEmail` (spoken symbols in en/hi/mr, provider names, `fixEmailDomain`), `emailUsername` + `emailProvider` (username alone → “which provider?”), `spokenEmail` (letter-by-letter read-back); the AI handles what the rules can't. `pnpm demo` builds the site and runs one server on :3000; `pnpm dev:all` runs `next dev` + the API for development.
- `design/specify-reference/`: the original static Specify-style mockup, kept for visual reference.
- `example_forms/`: real test forms (ECI Form 6, a flat PDF).

## Commands

- `pnpm test`: core unit tests (Vitest)
- `pnpm --filter web build`, then `pnpm --filter web start`, then `pnpm --filter web test:e2e` and `test:a11y` (Playwright via the installed Edge; `BROWSER_CHANNEL=` uses Playwright's Chromium; `BASE_URL` defaults to `http://localhost:3000`). `test:extension` loads the built extension and fills a live Google Form through Bolu (needs Playwright's full Chromium).
- Next 16.4.3 stops `dev`/`build`/`start` once with a security-upgrade notice; rerunning continues. `next dev` also writes `apps/web/AGENTS.md` and rewrites `next-env.d.ts`; don't commit those.
- Groq: `GROQ_CHAT_MODEL=openai/gpt-oss-120b` (verified 2026-11-01; `llama-3.1-8b-instant` is not available to this key). Orpheus TTS needs its terms accepted in the Groq console. Free-tier per-minute token limits are tight, so PDF extraction runs one page per request.
